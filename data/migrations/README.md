# Миграции релиза 0.0.2 — комментарии от 18.09.2026

Применённые SQL-файлы неизменяемы: механизм восстановления проверяет их SHA-256.
Пояснения добавлены здесь, чтобы документирование не нарушило проверку схемы.

| Файл | Изменение |
|---|---|
| `003_hex_metadata.sql` | Таблицы территорий и стартовых бароний; удаление устаревшего поля пресной воды, сохранение прочих метаданных; заполнение отсутствующих координат полотна; нормализация категорий |
| `004_user_admin.sql` | Русские названия групп; аудит административных изменений аккаунтов |
| `005_user_deletion_audit.sql` | Сохранение аудита после удаления аккаунта: nullable ссылки с `ON DELETE SET NULL`, отдельный логин участника |
| `006_player_onboarding.sql` | Название территории, герб, цвет и дата согласия баронии; перенос сведений о баронии в принадлежащие игроку гексы |
| `007_player_cabinet.sql` | Аудит смены герба и отказа от баронии без паролей и секретов |
| `008_player_barony_rename.sql` | Разрешение события переименования в аудите баронии |
| `009_crest_catalog.sql` | Каталог WebP-гербов, контроль хеша и размера файла, признак доступности |
| `011_armies_and_units.sql` | Каталог военных юнитов из первого листа Google-таблицы, генералы игроков и состав армий до пяти юнитов |

Перед применением создайте резервную копию PostgreSQL. Применяйте миграции
штатным механизмом по порядку, через обязательный runner. Данное документирование
не запускает миграции и не изменяет БД.
