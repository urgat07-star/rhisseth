# Таблица гексов и начальные баронии

Карта: https://rhisseth.ru/interactive-map/. Административная таблица:
https://rhisseth.ru/admin/hexes. Для таблицы требуется роль admin/moderator.

Карточка открывается правой кнопкой или клавишей Enter на выбранном гексе.
Характеристики доступны для просмотра. Географическое название редактирует
администрация отдельной кнопкой с подтверждением; название своей территории
может менять владелец. Это независимые поля. Владелец начальной баронии
переименовывает сразу её гексы, которые продолжают ему принадлежать.

В таблице найдите гекс и нажмите «Редактировать». Для составного ландшафта
добавьте части и укажите проценты с общей суммой 100%. Карточка позволяет
скрывать проценты. Для острова выберите «Остров: Да»: его категория — побережье.
Категории только три: суша, побережье, море. Пресная вода удалена.
Гексы с неизвестными характеристиками отмечены «Требует описания».

Для общего географического названия отметьте гексы и нажмите
«Название выбранных гексов». Для компьютерного владения выберите 2–10
соседних связных гексов и «Создать / изменить владение». Размер определяет тип:
баронство 2–3, княжество 4–6, королевство 7–10. Для изменения существующего
владения укажите его ID: текущие название, правила и выбранные гексы загрузятся.
Правила сохраняются как текст; симуляция компьютерного игрока ещё не реализована.

Нажав «Начать игру» на карте, игрок получает титул «Барон» и одну баронию
из 2–3 соседних свободных гексов. Можно выбрать предложенный вариант либо
получить случайный. Состав проверяется повторно при подтверждении;
повторное получение начальной баронии запрещено.

Административные формы защищены CSRF, серверными проверками ролей и
проверкой ревизии гекса. При ошибке 409 обновите страницу и проверьте данные
перед повторным редактированием. Изменения параметров не перерисовывают PNG.

Миграция: `data/migrations/003_hex_metadata.sql`. Создаёт `territories`,
`player_baronies`, материализует 465 гексов сетки, удаляет поле пресной воды
и приводит существующие категории к доле суши. Старые записи вне видимой сетки
сохраняются в БД. Миграцию выполнять отдельно от старта приложения.

Изменения опубликованы через обязательный runner проверенным пакетом.
Перед следующим обновлением через Git согласуйте серверные правки и карту V6
с выпуском репозитория. Резервные копии и журналы размещены внутри проекта.
