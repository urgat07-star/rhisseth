## Применённые изменения

- Установка пакетов `acl` и `sshpass`.
- Группа `rhisseth-team` и персональные Linux-учётные записи администраторов.
- Корневой, недоступный сотрудникам для изменения помощник проверки личности
  `/etc/rhisseth-game-access/identity.py` и таблица соответствия ID.
- Изменение `/etc/pam.d/sshd`: только группа проекта проверяется по игре,
  остальные пользователи проходят существующую проверку.
- Файл `/etc/ssh/sshd_config.d/00-rhisseth-team.conf`: парольный вход для
  группы проекта; вход ключом, forwarding и пользовательский SSH rc отключены
  для этой группы. Существующие параметры других пользователей сохраняются.
- Запись в каталоги проекта `app`, `data`, `docs`, `deploy` через ACL с
  наследованием прав. Корень checkout и `.git` остаются без права записи.
  Доступ к секретам и резервным копиям через файловые права не выдаётся.
- Служба и таймер `rhisseth-game-access-sync`, работающие от `root` каждые
  примерно 30 секунд. Они создают новые учётные записи для администраторов и
  блокируют утратившие право доступа.
- При снятии роли, удалении пользователя или изменении логина новые входы
  запрещаются по актуальной базе. При ближайшей синхронизации старые сеансы
  и процессы этой учётной записи принудительно завершаются. Их файлы сохраняются.
- `sshd -t` и reload SSH после успешной проверки. Перезагрузка VDS и перезапуск
  приложения для настройки доступа не запланированы.

## Существенные последствия

Назначение роли `admin` в игре будет одновременно выдавать SSH и право менять
код работающего сайта. Сотрудники смогут нарушить работу приложения; через
изменение исполняемого кода они потенциально получат секреты и данные, доступные
службе `rhisseth`. Файловые ограничения не изолируют автора кода от приложения.
Системный `root` и `sudo` сотрудникам не выдаются. SSH предоставляет обычную
оболочку Linux и не ограничивается одним каталогом.

Недоступность базы запрещает новые входы сотрудников. Уже работающие процессы
при недоступной базе могут продолжать работу: синхронизация не делает вывод
об отзыве роли без ответа базы. Смена пароля применяется к новым входам сразу,
но сама по себе не завершает уже открытый SSH-сеанс. Автоматическое создание
нового администратора обычно занимает до 30 секунд плюс время выполнения.

## Проверки выпуска и восстановление

Скрипт создаёт временного администратора с вымышленным адресом, проверяет
успешный SSH, отказ неверного пароля, SFTP upload/download/delete, отсутствие
прямого чтения файла пароля базы, записи в `.git` и `sudo`. Проверяет, что смена
пароля и снятие роли немедленно меняют результат нового входа. После проверки
временные аккаунты и файлы удаляются; существующие игровые пароли не меняются.
Все перечисленные проверки прошли на временном аккаунте. Проверено также
завершение открытого SSH-сеанса после удаления аккаунта и синхронизации.

Перед настройкой сохраняются PAM и основной конфиг SSH в
`/opt/rhisseth/backups/game-access-20260918-133526/`. При ошибке интеграционной
проверки предусмотрено восстановление PAM, удаление добавленного SSH-конфига,
отключение таймера и блокировка созданных учётных записей. Установленные пакеты,
группа, ACL и вспомогательные файлы при таком восстановлении остаются; полный
откат требует отдельного проверенного действия с учётом новых рабочих файлов.

Журналы сохраняются на runner и VDS в `reports/automation-logs/YYYY-MM-DD/`,
вывод контроллера — в одноимённом каталоге проекта. Пароли и хеши не выводятся.
Синхронизация записывает ежедневный журнал `game-access-identity-sync.md`; отказ
записи останавливает изменение учётных записей.
