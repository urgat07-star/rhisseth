# JavaScript фронтенда Rhisseth

Документ служит картой клиентского кода в `app/frontend/`. Скрипты работают
непосредственно в браузере, без сборщика и модульной системы. Поэтому имена
функций и переменных находятся в глобальной области конкретной HTML-страницы,
а порядок подключения скриптов имеет значение.

## Общие правила

- Сервер остаётся источником истины: браузер получает состояние через `/api/*`
  и после мутации заново загружает затронутые данные.
- Изменяющие запросы передают CSRF-токен, полученный из `/api/me`.
- Текст из API выводится через `textContent`; это не позволяет данным стать
  исполняемым HTML.
- `cache: 'no-store'` используется для состояния игры и справочников, которое
  не должно браться из кэша браузера.
- Ошибки API преобразуются в `Error` и показываются в статусной области текущей
  страницы.

## Файлы и ответственность

### `app.js` — интерактивная карта и игровой ход

Главный клиентский контроллер карты. Файл содержит несколько связанных блоков:

1. Геометрия гексагональной карты (`cellKey`, `hexCorners`, `polygonPoints`) и
   построение SVG (`render`).
2. Создание баронии: загрузка доступных клеток, проверка связности 2–3 гексов,
   случайный выбор и отправка формы (`connectedSelection`, `chooseHex`,
   `claimBarony`).
3. Границы и гербы владений (`redrawBaronyBoundaries`,
   `redrawBaronyEmblems`). Общие рёбра соседних гексов исключаются, поэтому
   рисуется только внешний контур территории.
4. Карточка гекса и административное редактирование (`showCard`, `closeCard`,
   обработчик `hex-form`). При сохранении передаётся ревизия записи для защиты
   от перезаписи параллельных изменений.
5. Армии на стратегической карте (`createMapUnit`, `syncArmies`,
   `handleGameHexClick`, `showHexActions`). Клиент подсвечивает допустимые цели,
   но окончательную допустимость движения определяет API.
6. Глобальные ходы (`refreshGameClock`, `startSkipCountdown`) и действия
   «завершить/пропустить ход».
7. Тактический бой (`openBattle`, `renderBattle`, `battleUnitClick`,
   `battleMove`, `battleCommand`). Состояние боя обновляется ответом сервера.
8. Начальная загрузка (`loadData`, `setupPlayerPage`) связывает личность,
   карту, ресурсы, армию и активный бой с элементами страницы.

Координаты карты осевые: ключ клетки имеет вид `q,r`. Тактическое поле использует
отдельные координаты `x,y`; смешивать эти системы нельзя.

### `cabinet.js` — личный кабинет игрока

Управляет вкладками кабинета и четырьмя областями данных: аккаунт, барония,
армия и дипломатия. `api` — единая обёртка запросов; `renderCabinet` заполняет
данные аккаунта и владения; `renderArmy` и `openGeneral` строят интерфейс найма
и состава отрядов. `action` унифицирует отправку форм с блокировкой повторного
нажатия. Отказ от баронии защищён текстовым подтверждением и флажком.

### `admin.js` — администрирование карты и правил игры

Загружает гексы и владельцев, строит таблицу, открывает редактор одного гекса и
выполняет групповые операции. Дополнительные секции администратора управляют
территориями NPC, календарём, балансом грабежей, речными связями, стартовыми
зонами и тестовым сбросом бароний. `mutation` централизованно добавляет CSRF и,
для гексов, заголовок ревизии.

### `users.js` — пользователи

Поиск и постраничная таблица пользователей, редактирование логина, почты, роли
и пароля, а также удаление аккаунта. Поле `expected` содержит исходные значения
редактируемой записи и позволяет серверу обнаружить конфликт изменений.

### `generals-admin.js` — справочник генералов

Показывает карточки шаблонов генералов, создаёт форму из `fields` и приводит
числовые поля к `Number` перед отправкой. Поддерживает создание, изменение и
удаление шаблона. Это справочник типов, а не список нанятых игроками генералов.

### `units-admin.js` — справочник боевых единиц

Показывает и редактирует шаблоны юнитов. Связь `upgrade_from_unit_id` задаёт
предыдущий тип в цепочке улучшения. Здоровье существующего типа намеренно не
отправляется при редактировании, а доступность управляет показом юнита для
найма.

### `resources-admin.js` — справочники ресурсов

Обслуживает два каталога: добываемые (`extractable`) и производимые
(`produced`) ресурсы. Набор полей задаётся схемой `schemas`. Код существующего
ресурса неизменяем и используется как идентификатор API.

### `admin-nav.js` — административная навигация

Получает текущую личность и показывает элементы с `data-admin-only` только
пользователю с ролью `admin`. Ошибка запроса оставляет ссылки скрытыми; скрипт
не является механизмом авторизации — доступ к API всё равно проверяет сервер.

## Как сопровождать

При добавлении нового сценария сначала выберите файл по ответственности выше.
Для новой самостоятельной страницы предпочтителен отдельный скрипт. Сложную
проверку правил игры следует реализовывать на сервере, а в браузере оставлять
предварительную подсветку и понятное сообщение пользователю. Новую функцию с
неочевидным контрактом документируйте JSDoc-комментарием: назначение, параметры,
результат и важные побочные эффекты.
