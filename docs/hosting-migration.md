# Перенос хостинга и пользователей

Источник: приватные `temp/hosting-bkp.zip` и `temp/sql-bkp.zip`.
Архив хостинга содержит PHP/MySQL-вход и регистрацию, оформление, старую карту
и её backup-пакеты. Перенесены исходные изображения/CSS и HTML-оформление.
PHP-выражения заменены Jinja2; файлы нормализованы из Windows-1251 в UTF-8.
Старый conn.php с параметрами MySQL, Apache .htaccess, старые CSV и backup
пакеты не публикуются. Текущая PostgreSQL-карта остаётся источником гексов.

MySQL-дамп не исполняется: `import_users.py` разбирает только ограниченные
INSERT-значения roles/users и записывает их параметризованно в PostgreSQL.
Новая миграция создаёт roles/users/user_sessions. Сохраняются ID, логины,
e-mail, bcrypt-хеши и role_id. Импорт в непустые аккаунты запрещён.
Исходный дамп содержит 2 пользователя и 3 роли: admin/moderator/user.
Персональные данные и исходные хеши не входят в репозиторий и журналы.

Вход /index.php (корень перенаправляет туда), регистрация /register.php.
После входа — /interactive-map/. Старый /map/interactive-map/index.html
перенаправляется на текущую карту. Без сессии карта перенаправляет на вход,
API возвращает 401. Admin/moderator могут менять гексы, user имеет просмотр.
В исходном архиве были названия ролей, но не таблица детальных разрешений;
эта политика — принятая для первого переноса интерпретация.

Сессии: случайный opaque cookie, только SHA-256 token в PostgreSQL,
12 часов, Secure/HttpOnly/SameSite=Lax. После входа token заменяется;
выход уничтожает сессию. Формы и PUT защищены CSRF; nginx ограничивает
частоту POST к формам входа/регистрации. Регистрация не принимает роль клиента.
Старые PHP bcrypt `$2y$` проверяются совместимой библиотекой:
[bcrypt documentation](https://pypi.org/project/bcrypt/).

Операция `hosting` в проверенных scripts/automation/Deploy-Rhisseth*.py:
backup БД/nginx, передача архивов через runner, fetch/fast-forward GitHub
на VPS, зависимости, миграция и импорт, отдельный vhost nginx, restart API.
Исходные архивы хранятся на VPS в /opt/rhisseth/temp с ограниченным доступом.
После переноса старая общая Basic Auth больше не нужна: доступ даёт сайт.
Временный TLS сохраняется до настройки DNS и публичного сертификата.

Перед выдачей доступа команде проверить: реальные логины владельцев,
правильность ролей и внешний вид в браузере. Plaintext-пароли исходных
пользователей не известны контроллеру и не сбрасываются. Проверки входа
выполняются временными синтетическими аккаунтами; затем они удаляются.
Сверка исходных пользователей проверяет все поля без раскрытия значений.

Откат: сохранить новый дамп, вернуть предыдущий проверенный Git SHA
и nginx vhost из /opt/rhisseth/backups, restart API/reload nginx после nginx -t.
Новые таблицы совместимы со старым приложением и могут оставаться; их удаление
потеряет регистрации и сессии, поэтому не является автоматическим откатом.
Для данных требуется отдельный согласованный restore.
