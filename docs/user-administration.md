# Управление пользователями

Панель: https://rhisseth.ru/admin/users. Войти обычным аккаунтом администратора; отдельного пароля панели нет. На карте доступна ссылка «Административная панель». Модератор по этой ссылке открывает таблицу гексов.

## Работа

1. Найдите участника по части логина или e-mail, при необходимости выберите группу.
2. Нажмите «Редактировать», измените логин, e-mail или группу.
3. Нажмите «Сохранить». Чужие сеансы после изменения завершатся; участник войдёт заново.

Собственную группу понизить нельзя. Последний администратор защищён от понижения. Занятый логин/e-mail и одновременное изменение другой администрацией возвращают конфликт без частичного сохранения. При конфликте обновите список через «Найти» и повторно откройте запись. Изменение e-mail не подтверждает новый адрес. Для смены пароля заполните «Новый пароль» и его подтверждение. Минимум 8 символов, максимум 72 байта UTF-8. Оба пустые сохраняют прежний пароль. Все сеансы после смены завершаются, включая собственный; потребуется новый вход.

Кнопка «Удалить пользователя» требует отдельного подтверждения. Она удаляет аккаунт, сеансы и стартовую баронию; все гексы игрока становятся нейтральными. Самого себя и последнего администратора удалить нельзя. Событие остаётся в журнале без e-mail и пароля; после удаления ссылка на аккаунт в старых событиях очищается. Блокировка отдельной функцией не реализована.

## Разработчикам

`admin_users.py` включён в `main.py`. Middleware проверяет действующую PostgreSQL-сессию, группу и `X-CSRF-Token`. Для изменения дополнительно проверяется роль инициатора внутри транзакции. SQL параметризован; текст в таблице вставляется через `textContent`. Регистрация остаётся только в группе `user`. Модераторы сохраняют права карты и владений.

`GET /api/admin/users?q=&role=&page=1`: поиск по логину/e-mail без учёта регистра, фильтр `admin/moderator/user`, 50 записей на страницу. Ответ: `total`, `page`, `page_size`, `users` с `id/login/email/role`. Пароль и хеш никогда не возвращаются.

`PATCH /api/admin/users/{id}`: JSON с `login`, `email`, `role`, `expected`. `expected` — прежние значения трёх этих полей, полученные из списка. Необязательные `password` и `password_confirm` назначают новый пароль при совпадении; оба пустые сохраняют текущий. Успешный ответ также содержит `reauthenticate`: true при смене собственного пароля. Обязательный заголовок `X-CSRF-Token` из `/api/me`. Ошибки: 400 — формат, 401 — нет сессии, 403 — права/CSRF, 404 — участник отсутствует, 409 — конфликт или запрет понижения, 413 — размер, 503 — база/роли. Успех: `{"saved":true}`.

`DELETE /api/admin/users/{id}`: обязательный `X-CSRF-Token`; доступен администратору. Удаляет пользователя, его сеансы, стартовую баронию и освобождает все гексы с этим владельцем. Ответ: `deleted` и `released_hexes`. Ошибки 409 возвращаются для собственного аккаунта и последнего администратора.

Миграция `004_user_admin.sql` переводит имена групп на русский и создаёт `user_admin_audit`. Аудит: ID инициатора и участника, timestamptz, имена изменённых полей, прежняя/новая роль. Полные прежние значения и секреты не сохраняются. Журнал пока доступен только системному администратору через БД; интерфейс просмотра не создан.

## Выпуск и восстановление

Развёртывание разрешено только через STU-AUTOMATION-01. Проверенные скрипты: `Invoke-UserAdmin.ps1`, `UserAdminRunner.py`, `UserAdminVps.py`, `VerifyUserAdmin.py`. Пакет имеет явный список файлов и baseline SHA-256; расхождение живой версии останавливает запись. До изменения создаётся pg_dump и копия прежних файлов. Миграция и проверки идут сначала на восстановленной отдельной базе, затем на рабочей. Перезапускается только служба приложения. Логи — `reports/automation-logs/`.

Резервная копия выпуска 18.09.2026: `/opt/rhisseth/backups/user-admin-20260918-095617/`. Откат требует отдельного проверенного runner-скрипта: восстановление прежних файлов из `files/`, перезапуск службы и проверка входа/карты. Миграцию и аудит можно оставить при откате к прежнему приложению. Полное восстановление БД из `database.dump` уничтожит изменения после резервирования, поэтому применяется только при согласованном восстановлении данных. Сервер при выпуске не перезагружался.

Дизайнеру: [полное описание интерфейсов](designer-handoff.md). Превью с вымышленными данными находятся в `reports/user-admin-desktop.png` и `reports/user-admin-mobile.png`.

Пароль хранится только как bcrypt-хеш с cost 12. Аудит содержит имя поля `password`, без значения и хеша. Проверка роли, изменение хеша, аудит и удаление сеансов выполняются одной транзакцией.
