# Создание баронии и личный кабинет игрока

Кабинет расширен и отделён от карты: [аккаунт, статистика, вкладки и отказ
от баронии](player-cabinet.md). При отсутствии баронии он больше не
перенаправляет автоматически на создание: управление аккаунтом остаётся доступным.

После успешной регистрации аккаунт получает серверную сессию и переходит
на `/interactive-map/cabinet.html`. Повторный вход игрока также открывает
кабинет. Если баронии ещё нет, доступны настройки аккаунта и ссылка создания
баронии. Администратор и модератор после входа также открывают кабинет;
карта доступна по ссылке из него, права редактирования сохраняются.

После первого визуального теста игрок задаёт только название баронии.
Отдельное поле названия территории убрано. Выделение земли не перезаписывает
существующие названия территорий: в сведениях о полученном гексе название
баронии отображается отдельной строкой сразу под территорией. Поля прежних
бароний в БД сохранены; новая миграция для этой правки не требуется.

## Выбор на карте

- Начальная барония сохраняет действующее правило размера: 2–3 гекса.
- Нажатие добавляет или снимает гекс. Выбор и снятие не должны разрывать
  связность; кнопка «Снять выбор гексов» очищает весь выбор.
- Доступны свободные описанные гексы суши и побережья, а также отмеченные
  администрацией островные гексы. Море без отметки острова, занятые гексы
  и гексы с неизвестной категорией недоступны.
- При открытии страницы сервер исключает гексы с владельцем или ID территории,
  даже если тип владельца ошибочно оставлен нейтральным. При подтверждении
  повторная проверка выполняется в транзакции; при конфликте интерфейс обновляет
  доступность и снимает выбор с уже занятых гексов.
- «Случайная барония» запрашивает актуальные свободные гексы и случайный связный
  набор из 2–3 гексов. Набор показывается на карте и сохраняется только после
  подтверждения. Можно повторить подбор или изменить выбор вручную.
- Соседство определяется шестью соседями в существующих координатах Q/R.
- Enter/Пробел выбирают гекс; Shift+Enter/Shift+Пробел открывают сведения.
  Правая кнопка открывает название, координаты, владельца, владение,
  территорию, категорию, ландшафт и объект.

Доступные гербы берутся из файлов `gerb_N.webp` в
`app/frontend/crests/`. Первый герб выбран изначально. Выбор герба предлагает
соответствующий цвет; игрок может изменить его через палитру. До сохранения
выбранные гексы получают лёгкую полупрозрачную заливку (14%), поэтому детали
карты остаются видимыми. Контур строится только по внешнему периметру баронии:
общие стороны соседних гексов одного владельца не рисуются. После сохранения
на карте остаётся насыщенный внешний контур сохранённого цвета.

Подтверждение условий создания обязательно. Это подтверждение размера,
смежности и однократности выбора; отдельный юридический текст пользовательского
соглашения в задании не предоставлен. Сервер сохраняет время подтверждения.
После создания кабинет показывает титул, название баронии, герб, координаты
и карту. Прежнее название территории показывается только при его наличии.
Оформление подложки и окончательный дизайн остаются задачей дизайнера.

## Хранение и выпуск

Миграция `009_crest_catalog.sql` создаёт каталог гербов с именем файла,
SHA-256, размером и признаком активности. Команда
`python app/backend/crest_catalog.py --check` только проверяет расхождения и
возвращает ненулевой код при их наличии. Команда с `--sync` добавляет новые и
обновлённые `gerb_N.webp`, а отсутствующие файлы помечает неактивными без
удаления истории. Штатный `migrate.py` синхронизирует каталог после миграций.

Миграция `006_player_onboarding.sql` добавляет название территории, герб,
цвет и время подтверждения в `player_baronies`. Для прежних бароний название
территории берётся из существующего имени; факт согласия не создаётся задним
числом. Метаданные гексов связываются с баронией по её ID и владельцу.

Выделение гексов выполняется в одной транзакции с блокировкой таблицы гексов
и записи пользователя. Сервер повторно проверяет наличие баронии, доступность,
смежность, размер, герб, формат цвета и согласие. Изменения API требуют CSRF.

Перед запуском этой версии требуется применить миграции штатным
`app/backend/migrate.py`, затем перезапустить приложение. Развёртывание и
проверки реальной БД выполняются через обязательный runner с журналом операций.
В рамках этой разработки инфраструктурные операции не выполнялись.

## Проверки

Локальные API-проверки: `test_player_onboarding.py`, `test_hex_metadata.py`
и `test_site_auth.py` — 19 тестов. База подменена тестовыми объектами;
интеграционная проверка миграции на PostgreSQL ещё не выполнена.

`scripts/check-player-onboarding-ui.py` проверяет локальные файлы в Edge
с перехваченными запросами и искусственными данными: смежность, запрет моря,
ограниченные сведения, герб, цвет, согласие, сохранение, кабинет и мобильную
ширину. Снимки находятся в `reports/player-onboarding-desktop.png` и
`reports/player-onboarding-mobile.png`.

Полный набор тестов на Windows не может загрузить существующий
`test_recovery_safety.py`: серверный скрипт восстановления импортирует Linux-модуль
`fcntl`. Остальные 24 теста при запуске полного набора прошли.
